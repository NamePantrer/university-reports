# Учебные отчёты, Университет ИТМО

Лабораторные и практические работы Петра Калинкина, факультет безопасности
информационных технологий (факультет БИТ), Университет ИТМО, группа N3249,
2026 год. В репозитории три дисциплины: операционные системы, теория
информационной безопасности и методология защиты информации, оценка
эффективности защиты информации.

Лабораторные по операционным системам выполнены вдвоём с Сергеем Евдокимовым
(в свойствах отчёта ЛР5 авторами указаны Калинкин Пётр Викторович и Евдокимов
Сергей Олегович). Практические работы по оценке эффективности защиты информации
в тексте отчётов отмечены как индивидуальные.

Это курсовые отчёты и файлы к ним. Кейс ООО «СеверМодуль» в работах по оценке
эффективности — учебная предметная область, одна и та же от ПР1 до ПР4.

У каждой работы свой каталог и свой `README.md`: что за отчёт, какие файлы
лежат рядом и какими командами пересчитать результат.

## Как разложены файлы

с номера: `ЛР` — лабораторная, `ПР` — практическая.

В каталоге работы обычно есть:

- отчёт в PDF и, где он сохранился, в DOCX;
- для ОЭЗИ — расчётная книга Excel, задание преподавателя, у ПР3 ещё презентация;
- `код/` — программы и скрипты;
- `данные/` — CSV, по которым отчёт строил таблицы;
- `материалы/` — памятки, анкеты, регламенты и другие текстовые приложения.

## Как открыть отчёты

PDF открывается в браузере на GitHub и в любом просмотрщике. DOCX, XLSX и PPTX
GitHub не показывает как документ: их открывают в Word, Excel, PowerPoint или
LibreOffice. Текстовые `README.md`, CSV, JSON и исходники читаются прямо
в репозитории.

Титульные листы из отчётов убраны. В PDF вырезаны титульные страницы (в ПР2
ОЭЗИ — ещё и пустая страница за титулом), в DOCX удалён титульный блок вместе
с изображениями подписей, в презентации ПР3 — титульный слайд. Нумерация
страниц в DOCX начинается с 2, как в исходниках, поэтому номера в содержании
остаются верными. У презентации ПР3 осталось 7 слайдов.

## Как запустить и собрать

Отдельной установки проекта нет: у каждой работы свои команды, они продублированы
в её `README.md`. Общее:

- Python 3.8 или новее. Расчёты ниже идут на стандартной библиотеке.
- `openpyxl` нужен только ключу `--xlsx` у `pricing.py`, `damage.py` и
  `efficiency.py` (книга Excel с формулами). Сами числа считаются без него.
- `matplotlib` нужен `ОС/ЛР5/.../код/score.py --plot` и графикам ЛР6.
  Сводная таблица ЛР6 (`summary_table.py`) дополнительно использует только
  стандартную библиотеку; графики ЛР6 (`plot_compare.py`) — `pandas` и
  `matplotlib`.
- Программы на C собираются компилятором C11 (`cc` / `gcc`) через `make`
  в каталоге `код/` соответствующей лабораторной.

Пересчёт чисел, которые уже лежат в отчётах и CSV. Эти команды не трогают
диски и сеть:

```bash
python3 "ТИБиМЗИ/ЛР1_Базы_угроз_и_калькулятор_CVSS/код/cvss3.py" --lab
python3 "ТИБиМЗИ/ЛР2_РД_ФСТЭК_классы_АС_СВТ_МЭ/код/fstec_classifier.py"
python3 "ТИБиМЗИ/ЛР3_Экспертные_оценки/код/expert_methods.py"
python3 "ТИБиМЗИ/ЛР4_Деловая_игра_NotPetya/код/quest.py" --roles SOC,ADMIN --auto max

python3 "ОС/ЛР4_Планировщик_ввода-вывода/код/analyze.py"
python3 "ОС/ЛР5_Тестирование_файловых_систем/код/score.py"

python3 "ОЭЗИ/ПР1_Ценообразование_инфопродукта/код/pricing.py"
python3 "ОЭЗИ/ПР2_Ущерб_от_угрозы_ИБ/код/damage.py"
python3 "ОЭЗИ/ПР4_Эффективность_проекта/код/efficiency.py"
python3 "ОЭЗИ/ПР3_ТЭО_ИС_АудитИБ/код/auditib/auditib.py" --db /tmp/auditib.db demo
```

Проверки, которые лежат рядом с кодом:

```bash
python3 -m unittest test_cvss3            # из каталога код/ ЛР1 ТИБиМЗИ
python3 -m unittest test_fstec_classifier # из каталога код/ ЛР2 ТИБиМЗИ
python3 -m unittest test_quest            # из каталога код/ ЛР4 ТИБиМЗИ
```

Сборка стендовых программ (бинарники в репозиторий не коммитятся):

```bash
make -C "ОС/ЛР4_Планировщик_ввода-вывода/код"
make -C "ОС/ЛР6_malloc_free_и_аллокаторы/код" malloc_bench
```

Полный прогон ЛР6 (`make run` в том же каталоге) ставит четыре аллокатора и
пишет CSV и графики локально. В отчёте стенд — Ubuntu в VirtualBox, 2 vCPU,
i5-1135G7; пакеты из `README` этой работы: `libjemalloc2`, `libmimalloc3`,
`libtcmalloc-minimal4t64`, `python3-pandas`, `python3-matplotlib`. Готовых CSV
и рисунков в репозитории нет: абсолютные времена зависят от машины.

Скрипты ЛР4 (`run_schedulers.sh`, `control_series.sh`, `kyber_latency_target.sh`)
и ЛР5 (`fs_bench.sh`, `disk_image_ops.sh`) переключают планировщик блочного
устройства, сбрасывают страничный кэш или создают loop-образы, разделы и LVM.
Их запускают от root и только на тестовом стенде. Замеры ЛР4 и ЛР5 в отчётах
сняты в Kali Linux под WSL2 (сентябрь–октябрь 2026). Повторный прогон на другой
машине даст другие абсолютные цифры; скрипты `analyze.py` и `score.py`
пересчитывают уже сохранённые CSV.

## Операционные системы (ОС)

Замеры подсистем ядра Linux: планировщики ввода-вывода на WSL2 и сравнение
аллокаторов в VirtualBox.

| Работа | Тема | Что лежит рядом |
|---|---|---|
| [ЛР4](ОС/ЛР4_Планировщик_ввода-вывода/) | Планировщики `none`, `kyber`, `bfq`, `mq-deadline`; целевая задержка чтения Kyber 2 мс → 1 мс | скрипты переключения и замеров, C-программы прямого чтения, патч `kyber-iosched.c`, CSV, `analyze.py` |
| [ЛР5](ОС/ЛР5_Тестирование_файловых_систем/) | ext4, XFS, btrfs, F2FS на loop-образах; отдельно NTFS, kpartx и LVM | скрипты образов и fio, `score.py`, CSV от 2026-10-02 |
| [ЛР6](ОС/ЛР6_malloc_free_и_аллокаторы/) | `malloc` / `free` для 503 размеров; glibc, jemalloc, mimalloc, tcmalloc через `LD_PRELOAD` | `malloc_bench.c` из приложения отчёта, скрипт прогона, графики и сводные таблицы |

По контрольной серии ЛР4 лучший средний `hdparm -t` у BFQ (3514,96 МБ/с).
По интегральной оценке ЛР5 лучшая ФС на том стенде — F2FS (S = 0,966).

## Оценка эффективности защиты информации (ОЭЗИ)

Сквозной учебный кейс: малое производство ООО «СеверМодуль», Санкт-Петербург
(сборка шкафов управления и модулей учёта доступа). Работы сдавались
RAR-архивами `oezi_pr1.rar` … `oezi_pr4.rar`. Здесь лежит распакованное
содержимое: отчёт (DOCX и PDF), исходная расчётная книга Excel, задание
преподавателя; у ПР3 ещё презентация. Имена файлов в архиве ПР1 были вида
`Калинкин_ПВ_ПР1_ОЭЗИ.*`.

| Работа | Тема | Что лежит рядом |
|---|---|---|
| [ПР1](ОЭЗИ/ПР1_Ценообразование_инфопродукта/) | Цена видеокурса «Аудит ИБ на малом производстве» четырьмя способами из методички | `pricing.py`, книга с формулами, программа курса, чек-лист обхода цеха, шаблон регламента резервного копирования |
| [ПР2](ОЭЗИ/ПР2_Ущерб_от_угрозы_ИБ/) | Ущерб от шифровальщика на инженерном сегменте и упущенная выгода, формулы (1)–(4) | `damage.py`, книга с формулами, служебная записка об обосновании СЗИ |
| [ПР3](ОЭЗИ/ПР3_ТЭО_ИС_АудитИБ/) | ТЭО ИС «АудитИБ» по ГОСТ 24.202-80 | схема SQLite и прототип `auditib.py`, регламент аудита, план-график работ |
| [ПР4](ОЭЗИ/ПР4_Эффективность_проекта/) | Показатели по пособию Павловой Е.А. (п. 4.2 и 4.4): Qk, RI, ARR, PP, NPV, PI, IRR, DPP | `efficiency.py`, книга с формулами Excel (`NPV`, `IRR`) |

Цены ПР1, которые печатает `pricing.py`: 3800 / 2200 / 5556 / 6000 руб.
В ПР3 и ПР4 инвестиции I₀ = 480 000 руб., NPV = 185 354 руб., PI ≈ 1,39,
IRR ≈ 31,4 %.

## Откуда взялись сопутствующие файлы

Отчёты — сданные работы, с вырезанными титульными листами, как описано выше.

Часть файлов в `код/`, `данные/` и `материалы/` подготовлена вместе с
репозиторием по тексту отчётов и сверена с числами в этих отчётах. Исходные
замеры экспериментов взяты из таблиц отчётов. Код из приложений ЛР6 по ОС
перенесён без изменений логики (добавлены комментарии). Скрипт из приложения А
ЛР4 и команды из приложения А ЛР5 оформлены в запускаемые скрипты с проверками.
Книги `*_расчет_формулы.xlsx` повторяют исходные расчётные таблицы формулами
Excel. Остальные скрипты, шаблоны, анкеты и сценарии в этих трёх каталогах
созданы при подготовке репозитория; у каждой работы в её `README.md` подписано,
какой файл из архива, а какой собран по отчёту.
